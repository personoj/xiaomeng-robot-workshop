# 固定工位间歇点焊

## 本轮确认与流程

讨论067–068明确纠正：焊段是一小条一小条、相互间隔，从右向左覆盖约2.4m管缝；焊接时底盘固定。召唤小萌H7在固定出生位出现，接到指定管排与焊缝后驶入相应工位，再执行机械臂程序。

每缝布置14段、每段32mm，中心从+1.15m到-1.15m，总焊肉约0.448m，间隔约145mm。程序每段先就位、短距离起弧、停弧退离65mm，再移到下一处。生成的焊肉来自已接受TCP采样；停止、暂停和段间空移不生长。末段结束后沿预检过的离壁通道撤回。

固定停车位在管排前方，车身旋转-90°。停车完成后，焊接、段间移枪和撤离阶段的底盘位置/朝向逐帧完全相同；服务端再次检查该不变量。机械臂FK和IK使用原厂连杆几何对应的六轴定义，管排全长未缩短。

## 管线与车轮

原走线不足以支持静止底盘的全宽横扫，重新设计为固定安装余量：主波纹管2.10m、红色供给管2.20m、送丝引导管1.25m。这是模型安装方案的修订；每次姿态求解保持各自总长，接头位置/方向固定。五次曲线容纳余量，主/红管分向机身外侧，送丝线保留导向路径。检查最小弯曲半径、管线互碰/自碰、连杆/线盘/机箱、焊枪与非相邻连杆、工件、支架底脚和房间障碍。

轮胎、轮毂和胎纹放在独立rotor组，轮罩/支架固定在assembly。滚动角为车身轴向有符号位移除以0.254m半径，不再只看世界X增减；正行、倒退、旋转车身后的方向均验证。

## 同一世界的三个视角

- 场景1：抓取台近景。
- 场景2：当前全部道具与机器人总览，支持五个管排工位。
- 场景3：当前任务目标管排的焊接近景；切换到另一个管排任务时对准相应工位。

`switch_workshop_view` 是纯镜头命令，焊接中也可使用。单独view_revision不使场景参数决策作废，不改变task_id、MuJoCo状态、对象身份或焊肉。

管排工位中心X为1.1、4.5、7.9、11.3、14.7m，均在同一扩大房间。对象ID与工位号分离，删除不会改动其他编号，空工位可复用。先后添加五个管排会得到管排1至5。语音“管牌”归一为“管排”，“最上面/最下面”对应1/7号缝。H7/H七明确视为型号，不当作7号对象。

## 验证

7条焊缝的完整路径，以及五管排同时存在时第5工位的路径通过预检。每条得到14个独立焊肉mesh，方向从右向左、覆盖两端，段间没有连接焊线，所有非驶入帧底盘完全固定。管长误差小于0.05mm，接头误差为浮点精度，TCP对缝误差小于0.02mm。

实际决策API已正确解析“召唤小蒙H7”和“焊管牌一最上面的那个缝”。“焊管牌五最上面的那条缝”也解析为panel_5、seam1。本机主服务完成点焊全流程；暂停期间切换全部三个视角，帧索引、底盘、焊肉长度不变，恢复后完成14段。原始证据`.local/stitch-live-proof.json`，实际运行scene_id保持原值。

6项Python工作坊检查、3项前端控制检查、车轮方向/固定轮罩检查、各条点焊几何检查通过。原721帧六轴模型运动回归仍通过，无效姿态仍被拒绝。新焊枪与非相邻零件净空检查覆盖同批姿态。

这是受约束运动学演示，不是实体焊接工艺或软管材料动力学认证。此次没有重新进行ESP32口述/声学验收；没有改动8766、设备固件或Key。
