# 持续机器人工作坊

## 实现分工

前端 `workshop-controller.js` 提供高层工具。讨论085后，明确新增的类型/颜色可由语音Agent直接填写受约束参数，本地校验执行；复杂操作继续传单步用户意图。后端 `workshop_decision.py` 将语音、对象清单、编号/位置事实和有限合法选项一并发送到千问。源/目标合并为一个对象对选择，避免两个独立选择互相矛盾。输出通过编号、唯一性、场景版本校验后才交给动作模板。

没有实现 ASR 阶段的推测并行或每帧模型决策，也未把接口耗时称为完整语音响应时间。模型失败直接反馈，不暗中回退成看似模型成功的规则答案。

`workshop.py` 管理稳定 ID、递增编号、任务去重、版本及持久化；`workshop_physics.py` 在同一个 MuJoCo 模型内预分配物体槽。增删道具、入盘和叠放不重新创建物理世界。机械臂的 IK、接触和碰撞预演沿用上游技能，并针对球的接触支持修正 TCP 和夹爪力、细化笛卡尔搬运步长；没有把物体吸附到手上。

`workshop-scene.js` 把物理抓取台、小萌 H 资产和管排放在统一房间内。编号通过射线悬停显示，底部实际三维资产渲染为缩略图。机器人移动车轮随路程滚动，底盘轨迹为预设通道中的运动学动画。

## 已完成验证（2026-10-11）

- 四项 pytest 检查通过：持续身份和存储、球抓放后同场景方块叠放、暂停恢复与车辆入场、缺失/含糊/复合指令校验。物理验证包含双侧抓持、抬升、支撑接触、稳定、释放和撤离，未允许的碰撞为零。
- 实际 HTTP 决策接口选中“蓝色二号球 → 红色一号托盘”，实际主服务完成物理搬运；再次选中“红色一号方块 → 蓝色一号方块”，主服务完成叠放。两个任务的 scene_id 相同。
- 后续实际模型调用添加黄色一号球，再精确删除；原有对象 ID 列表保持不变。蓝球99被场景校验拒绝，没有发出动作。
- 小萌 H 从停靠位驶入指定工作位。车辆到位被标为运动学展示，未混称为 MuJoCo 验证。
- 模型原始20题评估：基本提示15/20；增加编号/位置等事实后17/20。剩余错误包括含糊指代与多步指令。程序 guard 对这些情形拒绝直接执行，这不等于模型原始准确率100%。该集合是小规模人工用例，不能代表通用中文能力。
- 增强提示评估的预热后端到端中位数524.8ms；服务器报告耗时与端到端耗时分开记录。实际入盘首请求1269.7ms（服务器88.7ms），叠放首请求1226.4ms（服务器81.2ms）。网络、冷连接和输入长度都会影响结果。
- 三项前端控制检查通过：含糊对象不提交动作、决策保留原场景版本、回执丢失标记unknown且不自动重复操作。
- 生产构建通过，页面已检视实际缩略图、悬停显示以及独立焊接效果。图像与原始测试结果保存在忽略提交的 `.local/`。

此次浏览器测试页遇到同会话 page 通道已被其他页面占用，未抢占连接，也未重启8766。模型 API 与物理执行测试不能替代新的 ESP32 语音/收音验收。

## 明确边界

- 抓取台当前使用6个预设小件候选位置、2个托盘位置，满位明确拒绝；大房间不意味着任意位置均可到达。
- 方块可以叠在方块上；球需要托盘。路径不可执行时保留现场并返回错误。
- 移动车底盘没有轮胎接触动力学与通用避障规划。
- 管排默认未焊。指定焊缝的模型执行和光效已接通，接口中 `welding_execution=true`、`welding_mode=checked_kinematic_simulation`；详见 WORKSHOP_WELDING.md。
- 场景持久化包含对象和qpos；不恢复进行中任务。讨论078–079将归零改为清空全部可召唤道具及焊机，仅保留房间、工作台和白色机械臂；同一scene_id保留，回到抓取镜头。
- 密钥只读取本机外部文件，没有发往语音上下文或静态网页。用户明确保持现有Key。
