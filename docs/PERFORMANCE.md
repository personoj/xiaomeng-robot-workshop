# 工作坊性能优化

讨论085授权先保存Git，再按优先级实施。优化前检查点为 `6519e44`，包含 `c1fba5e` 的代码/模型与随后补入稀疏检出目录的参考文档；未推送远端。语音仓库修改前为干净的 `8ce3892`。

## 数据和画面

- `/api/workshop/assets` 返回当前运行期固定的几何、MuJoCo关节关系和槽位，一次加载、服务端缓存并gzip压缩。新增/移除道具只更改相应槽位的显隐与颜色，不重建Panda网格；新的后端runtime会重新同步资产。
- `/api/workshop/events` 推送轻量姿态，运行态目标30Hz、待机350ms一次。网络读取与工具执行独立。每包有runtime_id/sequence，迟到HTTP回执不会倒退画面。
- 以关节关系重建FK，显示端使用70ms缓冲插值，保持连杆局部尺寸和公共关节。不外推，暂停时直接冻结到已收到的真实状态；显示插值不写回MuJoCo。焊机仍使用原来的受约束姿态/定长管线逻辑。
- 焊迹按每条run的游标发送新增点；重连先发完整数据，之后增量，不靠丢点降低负载。
- 同类几何复用；删除独立模型时释放GPU资源；阴影在物体变动时更新，相机单独旋转复用阴影。移除主画布不必要的preserveDrawingBuffer。
- 道具库收起时不生成缩略图，也不预先下载20.46MB的焊机预览GLB；展开后按需加载。语音波形在静止时不重复绘制整套曲线。

## 指令等待

`add_workshop_object`支持受枚举约束的kind/color。明确参数由原语音模型给出、后端验证后直接新增，省去第二次参数决策；复杂描述仍只传request并走原decision-model-preview。未用关键词匹配代替模型理解。错误配色会拒绝，不静默换色。

工具执行回执与耗时绘图解耦，成功的执行不会因为渲染错误变成可重试的未知操作；显示异常另行提示。复杂决策后复用原expected_revision，撤掉重复状态读取，服务端仍校验版本。新增只读调试入口 `window.xiaomengPerformance.snapshot()`，记录最近绘图提交、资产构建、command/resolve各阶段时间；这些数字不是整条语音延迟。

Harness按键输入的first_audio_ms从有效input.commit开始计时，避免把用户按住说话的时间算进响应延迟。调整统计口径本身不代表提速。

## 本轮证据

- 资产解码内容28,310,687字节；浏览器实际传输由约28.31MB降为3,782,631字节（含响应头），减少约86.6%。压缩后首次冷缓存观察973ms、服务端缓存后观察51ms；仅作为本机样本，非稳定网络基准。
- 连续添加绿球和蓝盘后assetLoads仍为1；本地执行API回执6.3/5.9ms，抓放受理10.7ms。这些时间不含识别、语音模型或回复播放，不能与旧语音端到端数据直接比较。
- 真实语音模型文字入口参数校验：约1093ms返回kind=ball/color=blue，正确选择直接路径。此校验没有执行场景操作，也没有向设备播放音频。
- 实际MuJoCo绿球入蓝盘完成，support_contact=true、stable_seconds=1.748、held=false、forbidden_contact=false。临时绿球/蓝盘在验证后移除，原有蓝球/红盘保留。
- 四组MuJoCo姿态、143个几何变换与浏览器同用FK实现对照：最大位置差0.00792mm，旋转矩阵差约5e-7，处于导出数值舍入范围。
- 9项工作坊Python、7项Node控制/流式合并/FK检查、10项语音PTT/音量测试通过；生产构建通过。控制台无新增错误，道具库中的Panda缩略图在层级变换后仍正确。

本次没有得到可信的完整焊接场景P95帧时间或新的真人口述首音基准，因此不宣称已经稳定60fps，也不把本地API几毫秒当成用户体感响应。后续以一次相同口述和相同动作的短对照采样判断剩余瓶颈。

本机证据位于 `.local/performance-live-check.json`、`.local/fast-spawn-model-check.json`、`.local/physics-pose-fixture.json` 和 `.local/performance-workshop.png`。

统一启动入口同时修复了跨PowerShell进程捕获启动输出时的停滞，改为直接调用既有脚本；保留互斥、防重复进程和USB等待行为。
